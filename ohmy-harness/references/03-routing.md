# 03　交付方案、选模与反馈

## 3.1　先选方案，再找入口

为首选方案写三个字段：**改善的用户可见结果、所需能力、证明改进的验收项**。然后才查看[执行入口](07-executors.md)。需求简单时一句话即可。

| 场景 | 记录与行动 |
|---|---|
| 水墨主题的书展首页 | 原创图体现水墨主题；需要可验收的插画产物；核对主题识别、移动裁切、报名可见及可用 |
| 内部表单的通用搜索图标 | 复用匹配设计系统的图标；核对控件可识别、能操作 |

### 受阻后重新选路

先回看用户原话和已确认的验收项，判断换路后取得的证据还能否验证用户原本要验证的结果。用户点名要验证的对象或方法也属于验收范围。

- **能按原范围验收**：在已有授权内直接换路，记下替代入口及其能提供的验收证据，沿用原验收项。
- **替代方案会改变验收范围**：在制作或派发替代任务前先 grill 用户。另做一份只能验证部分目标的临时交付也适用。说明受阻项、替代方案能验证什么，以及哪些原要求仍待验证。一次只问一个决定性问题，让用户选择继续原方案或接受哪项变更。等答复时保留已有成果，只暂停依赖该决定的工作。用户确认变更后，记录决定和新的验收版本再执行。

## 3.2　按同类工作和验收选择

- 每张任务单先登记任务类型、难度、所需能力、验收版本与质量门槛、预算。阶段默认入口可参与候选。逐项核对候选的模型能力、工具、工作区权限及当前可调用性，再在满足用户授权、指定入口和项目限制的组合中选择。
- 按「执行入口配置 + 模型 + 推理设置」枚举候选。同一个原生子 Agent 入口可有多个候选，主控可用高推理档，子 Worker 可用该入口支持的轻量模型和低推理档。按具体入口和模型映射推理设置，仅支持默认设置时按默认值列候选。启动时应用选中的配置，回执能核实的实际设置另记。
- 同类样本不足时，按项目初始分工和实际可用的能力选择。例如，批量校对看规则执行的一致性，跨模块取舍看整合多方约束的能力。同一次尝试保持入口稳定。
- 优先考虑有多份同组证据、能稳定满足质量底线的候选，在其中比较总耗时和有数据的总成本。计入主控调度、各次尝试、返工和复核。任务墙钟时间和各次调用用量分别记录，并行耗时按实际区间统计。
- 在任务单里简记选择依据。只有一个符合要求的可用组合时，记明候选受限的原因。实际模型以可核实的启动记录或回执为准，无法确认时标为未知。规则明确的类名修改可用通用入口，首屏构图则单独核对能否读真实截图并做视觉判断。
- 组合验收导致任务重开，或相关入口恢复可用时，重新匹配受影响且尚未启动的任务和将开启的新尝试。处理已启动的尝试时沿用[异常规则](05-recovery.md)。

## 3.3　每个独立任务结算一次

- 达到验收通过、取消或确定失败时，以「项目标识 + 任务 ID」结算任务。任务账本保留所有尝试及归因，本机记忆按键更新摘要。重新验收、归因纠正和迟到的明确反馈更新原样本；重复处理同一结果样本数保持不变。
- 保留每次尝试的实际入口、模型与版本、推理档、起止时间、可得用量、结果和证据。记录该次是首次生产、原会话返工还是接手修复。实际用量不可见，或用户未反馈时，相应字段留空。
- 先核对原始要求、派单内容和候选版本，再归因。原因未核清时先记待定，据此判断该修任务单、恢复入口、回原会话返工或调整模型。

| 证据 | 归因与后续 |
|---|---|
| 原始需求有，派单漏写或上游输入缺失 | 调度或输入缺口，修正任务单，重算受影响摘要 |
| 限流、未登录或服务中断 | 更新入口健康和实际等待耗时；只有可复核产物进入模型质量比较 |
| 产物违反明确写入的要求 | 执行问题，附失败样例和验收证据 |
| 用户确认的风格偏好或验收决定 | 写入适用范围的项目决定，附明确反馈 |
| 审阅意见缺证据、现有信息无法定位原因 | 标记待定，补原始证据后再归因 |

例如，首个 Worker 漏掉任务单中一项，另一 Worker 接手修复通过。样本增加一份，两次尝试都进入交付总耗时，后者标记为接手修复。若查出要求漏写在派单里，改为调度归因，保留原候选与最终验收证据，以原任务键重算摘要。

## 3.4　收集可比较的独立样本

- 以适用项目范围、任务类型、难度及验收标准分组。候选区分模型版本与推理档；版本变动后为新版本积累证据。
- 对定位相近的候选，选择低风险、有可复跑验收且预算容许一次回退的任务。首轮对照固定候选和顺序，记录输入、工具权限、验收版本及实际入口。
- 多项独立任务均证实质量过线且交付总成本更优后，只更新这个任务组的默认分工并记依据。出现经核实的严重遗漏时按原因决定回退及重验。
