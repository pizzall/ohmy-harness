# 06　日常自检和机制验收

## 6.1　日常交付自检

| 检查 | 通过标准 |
|---|---|
| 可追溯 | 任务、尝试、原生会话 ID（如有）、候选版本和证据可定位 |
| 可复跑 | 在登记版本上用验收命令或明确的检查项得到对应结论 |
| 可结算 | 独立任务对应一个样本，返工贡献可查，未知用量和用户反馈留空 |
| 可集成 | 输入版本已验收，组合检查通过；受阻分支及影响有记录 |
| 可清退 | 有依赖的消费者均已完成，持久材料脱离临时目录仍能使用 |
| 可回读 | 需要续跑时，新会话能按记录找到已交付成果、决定和下一步 |
| 进度一致 | 已验收叶子数、分母变化、阻塞和组合状态与账本一致 |

## 6.2　验证 Harness 机制

- **M1 单 Worker 闭环**。完整小任务一次派给一个 Worker，主控独立验收；宿主独占工具的例外只覆盖对应步骤。验证首次已授权的业务产物可以提供能力证据，停用入口无调用，包括探测。
- **M2 多任务协同**。固定契约版本，核对两个就绪任务的实际运行区间重叠，组合验收晚于两项单独通过。核对共享临时输入等最后一个消费者，取消且无产物时留取消证据，重复清退后复验仍可运行。
- **返工与恢复回归**。在专门的用例送入坏候选、重复事件和旧尝试的迟到回包，确认原会话可返工、只有有效尝试能推进状态、每个任务只结算一份。人为造错只用于机制回归。
- **M3 后台托管**。有后续需求时单独验证关窗续接、完成事件回投和重复投递的处理。

## 6.3　同宿主对照

固定宿主及版本、任务文本、仓库基线、已授权入口、模型与推理档、预算、验收表和初始记忆。隔离两组产物与学习记录，交替跑 A/B 和 B/A，每次只改变一项规则。优先测试书展首页的「先选方案再匹配资源」，让两组各自面对生图可用与不可用。按同一验收表检查主题、移动裁切、报名，并核对缺口报告、独立分支进展和待决项。两组分别记录实际结果。

后续可对照整单委派、串并行或同档模型。每次记录运行 ID、基线版本、组别、唯一变量、计划与实际入口、起止时间、可得用量、返工、验收、用户反馈与证据。首轮用于检查流程；采用新默认前用多项独立任务复验，主观评价隐藏组别。
