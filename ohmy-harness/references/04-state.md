# 04　任务事实、产物、记忆与清退

## 4.1　写到哪，怎么定位

| 记录 | 放置位置 | 内容 |
|---|---|---|
| 项目任务事实 | 项目根 `.superagent/record.txt` | 目标、任务约束、依赖与版本、尝试、原生会话关联、状态、验收结论及证据、样本结算与更正 |
| 工作产物 | 交付约定位置或 `.superagent/artifacts/<任务ID>/<尝试号>/` | 正式产物、曾送验的候选版本、日志和复跑材料；用仓库标识与提交 ID，或从项目根可解析的引用与哈希定位 |
| 本机资源清单 | `~/.superagent/resources.json` | 入口标识、用户策略及来源、能力及最近验证时间、结果、失败原因和证据 |
| 本机模型记忆 | `~/.superagent/model_memory.json` | 同组候选摘要、模型版本与推理档、独立样本数、达标数、一次通过数、确认的严重遗漏、含返工的耗时与有数据的成本、样本引用、最近验证时间 |
| 项目决定与交接 | 项目已有决定记录与交接摘要 | 已确认的适用范围、来源、证据、确认时间、替代关系；交接另含未完项、下一步及稳定的证据入口 |

主控写任务事实和本机 JSON，Worker 交产物、提决定候选。沿用现有账本、任务约束、产物登记与尝试事件。旧记录缺模型、版本或用量时保留未知。更新本机 JSON 时先读现有记录，串行合并，于同目录完整写入临时文件后原子替换。写入受限时如实记录，已授权的工作可以继续。

项目事实以账本为准，先登记独立任务的结算或更正，再更新本机模型摘要。样本键为「项目标识 + 任务 ID」，证据指向项目记录。每次任务验收、取消或确定失败时按键更新；重验或迟到反馈更新原条目，同一结果重放保持计数不变。各次尝试的入口、用量、耗时与归因保留在项目记录。摘要写入失败可按账本样本重建。旧决策与新证据冲突时，按当期用户指令和有效项目约定核对，记录冲突和采用依据。

## 4.2　引用、转存与复验

- 产物登记创建者、版本或哈希、验收状态，按授权给下游只读引用或副本。下游核对版本和哈希；旧工作区回收后，引用仍可读。
- 正式产物、候选版本和验收所需脚本先转存到稳定位置，把复验使用的引用改到持久位置。主控在合适的基线与证据上复跑；语义检查按约定覆盖项、来源与事实复核。
- 单宿主同项目可用新会话回读交接。记录里至少有任务 ID、尝试号、原生会话 ID（如有）、已验收版本、决定、未完项、证据与下一步。

## 4.3　按尝试清退临时文件

探测、转接或批处理脚本放在项目根下 `.superagent/runs/<任务ID>/attempt-<号>/scratch/`。登记本次创建的具体文件、消费者、进程状态和清退结果。正式产物与复验必需脚本转存后再进入清退检查。

1. 核对尝试已结束、相关进程已退出、最后一个消费者已用完。待返工、下游仍引用或状态不明时保留现场。已取消且无产物的尝试，可只持久化取消证据。
2. 暂时移开该目录或在隔离副本中去掉对它的访问，用持久引用复跑必要验收。失败则恢复现场、修正引用后再检查。取消且无产物时核对取消证据可独立读取。
3. 删除前核对解析后的尝试目录与每个文件的绝对路径都在预期的项目运行目录和本次尝试内。跳过指向目录外的链接或重解析点。只删除本次尝试登记的临时文件，按需移除空目录。
4. 记录已清退、保留或失败项。失败可重试，每次重新核对边界；已清退且缺失的登记项按已处理记。

> 注：文件能否清退取决于最后一个消费者的状态。生产它的 Worker 先退出、或第一个消费者已通过，都不足以清退。
