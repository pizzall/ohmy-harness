# 07　执行入口、资源建档与能力证据

## 7.1　同一宿主冷启动

**登记项目审查 hook。** 首次派单前，在本次验收将使用的环境执行 `oma --root <项目> init`。Python 主控可用同一项目的 `coord.initialize()`。初始化用临时原件做两次验收。漏一项须被拦住，覆盖完整须能通过并留下逐项证据。两项都成立才返回 `ready`，并在项目的 `.superagent/review-hook.json` 登记实际入口。自检不计入项目进度。

每次冷启动或更换账本入口都重新执行，使用本次命令结果。若只有 skill 文本、命令不可用、返回失败或回执无法写入，记下缺口，审查留待核验。已授权的独立工作可以继续。修复后在同一项目重跑初始化即可。

**盘点 Worker 资源。** 读取 `~/.superagent/resources.json`，并只读盘点当前会话暴露的原生子代理、专用工具和本机可发现的 CLI。旧交接报告里的机器状态只作复核线索。当前授权以适用的资源清单和用户决定为准，登录态和会话可调用性以本轮核验为准。

- **清单缺失时**，在第一次派单前主动向用户索要。用户可以给出已有清单的路径或内容，也可以直接说明有哪些入口、各自配置了哪些模型与推理档。提问时附上已发现的候选和已有约束，请用户一次补充遗漏项并确认允许、停用及适用范围。按答复建档，尚未实测的能力标为待验证。用户暂缓建档时，仅用已明确授权且当前可调用的入口继续。
- **清单已存在时**，复用已确认的策略，结合项目约束核对当次会话可调用的入口。只向用户询问影响当前任务的缺项或冲突。

对每个涉及当前任务的入口分别核对四件事：

| 维度 | 记录内容 |
|---|---|
| 机器可发现 | 记录发现来源，CLI 记可执行路径，原生入口记宿主名和实际暴露的工具名。同一入口支持的模型在选模时分别枚举 |
| 会话可调用 | 原生工具当前实际暴露，或 CLI 有非交互、鉴权和目标工作区权限，记录其已知状态 |
| 用户授权 | 允许、停用、未确认及其来源和数据范围；项目约束可以收窄 |
| 具体能力已验证 | 能力名、所用入口或模型版本、最近实测时间、结果、失败原因及证据引用 |

主控把持久信息写入 `~/.superagent/resources.json`。机器上的发现结果可缓存；会话可调用状态按当前会话核对。用户或项目停用的入口在调用前剔除，真实调用次数为零，包括 `--help`、`--version` 和 Worker 探测。临时限流只更新对应入口健康，保留原用户策略和已有能力证据。

主控亲自执行的步骤只在任务记录中注明宿主、动作和结果。回读旧清单遇到 `self` 或“自身”时，保留历史记录，跳过该项；要派给同宿主的子代理，按当前会话实际暴露的入口另行核对。

## 7.2　匹配所需能力，再按产物验

1. 从任务单读取能力需求，筛出已授权、当前可调用且满足项目约束的入口。优先使用有对应产物证据的入口。
2. 能力尚未验证且输入和预算允许时，可把首件已授权的业务产物用作验证。通用文本探测结果只说明文字或基础通道可用，配置文件仅是线索。
3. 图像能力成功的证据是实际回读到**可解码的非空图像**。按任务单另验尺寸、格式、裁切和视觉效果。记录证据版本和检查结果；失败时更新该能力的验证记录并走[替代规则](03-routing.md)。临时入口故障按健康状态记录。
4. 探测或转接确需临时文件时按本次尝试的 scratch 目录登记，留存必要证据后走[清退条件](04-state.md)。

> 注：同一个入口的「能回文字」与「能交付图像」可以同时有不同结论。先记录证据对应的具体能力，便于下次继续判断。

使用现有 Python 能力探测时，`probe()` 的离线发现结果只用于盘点，`probe_with_worker()` 的通用回包只用于所测通道。任何真实调用前由主控执行用户策略和项目约束，具体能力以对应业务产物验证。

## 7.3　启动、结果与续跑

- 启动时限制任务工作区、允许的数据、读写边界、预算和超时。网络访问和其他仓库须有任务授权。原生 Agent 或专用工具用宿主的实际接口；CLI 读取结构化输出、退出状态和会话 ID（如有）。
- 取得候选版本、摘要与证据才转入验证。无可定位产物、环境错误和超时按[异常恢复](05-recovery.md)处理。
- 返工优先续跑原负责人原会话，并附失败样例、预期、实际、目标版本。需换手时把任务单、候选和证据交给已授权入口，登记新尝试与换手原因。
