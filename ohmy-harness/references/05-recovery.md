# 05　异常恢复、返工与取消

正常路径为「待调度 → 执行中 → 待验证 → 单项验收 → 组合验收 → 交付」。任务状态由主控按有效尝试写入。

| 事件 | 行动 |
|---|---|
| 产物可验证 | 对照任务单，在候选版本上独立复跑或按验收项复核 |
| 业务验收失败 | 写失败样例、预期、实际与目标版本，回原负责人原会话返工。保留失败证据。会话无法恢复时，按同样的任务单、候选和证据登记接手尝试 |
| 缺能力、权限、登录或环境资源 | 按[受阻后重新选路](03-routing.md#受阻后重新选路)判断能否改派。需要新权限时向用户申请，只暂停受影响的分支 |
| 短时限流或服务故障 | 记录到对应入口健康和实际等待耗时；按授权与预算恢复或改派，先核对原尝试。归因规则见[选模与反馈](03-routing.md) |
| 超时、断连、主控重启 | 标记待核对，查原会话、进程和工作区；确认旧尝试结束且可避免重复副作用后才重派。有结果就按原尝试收件 |
| 重复、乱序或迟到的回包 | 按任务 ID、尝试号和事件去重；当前有效尝试可推进状态，旧尝试仅留证。取消状态保持有效 |
| 用户取消 | 停派相关工作，核实在跑的 Worker，登记取消证据，结算本任务；确认清退条件后处理登记的临时文件 |
| 用户修改范围或共享契约变化 | 绑定新的验收或产物版本，只让实际消费旧版或受新范围影响的任务重验；保留历史尝试 |

首次执行之后最多两次业务返工。已核实的环境失败计入耗时和入口健康，业务返工次数按业务失败计算。退出成功但取不到可定位产物时按无产物失败处理。到返工上限保留最后候选和失败证据，主控核对责任与预算后决定收尾或找用户裁决范围。

### 长考与超时收件

派单时登记原会话或启动标识、工作区和每个预期产物的位置。将观察窗口和硬时限分开。按模型历史耗时、任务难度和用户预算安排下次查看，90 或 120 秒可以用作一次查看时间。长时间无 token 时保留原尝试，已有进度可拉长间隔。用户规定的截止时间、费用上限与供应商硬限制仍有效。宿主支持轮询时，保存运行句柄继续等。只支持短前台调用时，优先选择可续等的原生会话或作业入口。

Python 直调默认持续等待。显式传入的 `DispatchTask.timeout` 和 `Limits.max_timeout` 取较短的硬时限。触及时 ExecWorker 结束本地调用并记录已取得的会话 ID。远端是否仍运行由原入口核对。取消在跑任务时，主控还须通过原入口停止执行并核对退出。

1. 用 `oma --root <项目> scan` 找回任务、尝试、会话、工作区和预期产物。仍在跑就登记 `task reconcile --id T --attempt 1 --verdict running`，沿原会话等待。宿主等待超时且状态未明时登记 `--verdict unknown`。复用此前的读取结果，记录有变化的产物和下一次查看时间。
2. 回包或文件迟到时，先核对来源、版本以及每一个预期文件。原会话仍活动、仅有部分文件、归属不明时保留现场和缺项。运行日志能证明本次尝试已交回完整结果后，写收件凭据。路径相对本次工作区，哈希填实际 SHA-256。

   ```json
   {"task":"T","attempt":1,"session":"native-42","log":"run-1.log","outputs":{"result.md":"<64 位 SHA-256>"}}
   ```

3. 执行 `oma --root <项目> task reconcile --id T --attempt 1 --verdict recovered --candidate result.md --evidence receipt.json --by reviewer`。通过后原尝试进入待验证，沿用原验收。会话产物先导出到任务单上的持久位置。来源由核对者从原运行日志确认，账本比对任务、尝试、会话与文件哈希。
4. 原尝试已结束、预期产物无法收回、重复副作用已排除时，登记 `--verdict dead` 再 `task redispatch`。已被替代的尝试回包只留档。重派继承原范围和验收方法。

重启先盘点已派未回、待核对、阻塞和仍引用临时输入的尝试。用项目账本回放核对完整性；遇账本中间损坏先停写并诊断。待返工、仍有消费者或状态未明时保留临时现场，按[清退条件](04-state.md)逐项核对后处理。
