# 审查范围与放行

## 派单前的 grill

主控对照用户原话逐项确认三个问题。哪项用户可见的结果要验证？审阅者必须读哪些原件、执行哪项检查才能下结论？哪些事项已明确排除？现有材料能回答的直接填写。只有不同答案会改变交付时才问用户，一次问一项，并说明两种答案会怎样改变验收。可复用宿主已提供的 grilling 问法，也可直接按这三个问题完成。无人值守的重试沿用已确定的回答。

独立审查、组合审查、最终交付审查统一用 `--role review`。即使生产和审查由同一宿主承担，也要登记这次审查。创建时把每个可独立判断的“检查 × 原始对象”写成稳定 ID，明确来源、方法和成功条件。覆盖多份产物时逐一列出。运行、图像和外部来源用能复核的本地版本、原图、原始运行记录或原文快照。任务单同时保留原请求与范围依据，默认排除项可为空。

```json
{
  "items": {
    "argument": {"source":"out/report.md","method":"read-original","criterion":"核对结论是否由原文中的事实支持"},
    "replay": {"source":"out/run.log","method":"rerun","criterion":"独立复跑约定场景，核对实际结果"}
  },
  "excluded": ["正式环境部署"]
}
```

用 `oma --root <项目> task create --id audit --role review --intent "核对报告与运行结果" --review-scope scope.json` 登记。任务派发、重试及压缩后均可用 `oma --root <项目> task scope --id audit` 取回账本原件。交接可省略重复轮询输出，须保留任务、尝试、候选版本、完整范围、已有批次位置、缺项和下一步。

## 多份产物与再次产出

- 用户要求多份产物各自回答不同问题或体现不同内容时，把跨产物比对写进冻结范围。逐份登记原件和对应位置，写明要与哪些产物比较、哪些内容应有区别、哪些允许复用。审阅者对照原件，指出具体重复或差异。同一模板、不同文件名或不同哈希都不能单独判定内容是否雷同。
- 返工或重新生成后，沿用原验收项，按新候选送验。某份产物改动时，与它有关的跨产物比对也要重做。上一轮审查已结束的，另建审查任务并关联原任务。
- 阶段切换、新增产物或发现原要求缺少验收项时，先回读旧范围，把仍适用的原项与新增项一起登记到新版审查任务，再派单。记录原任务 ID 和变更依据，保留旧版。若变更涉及用户目标或验收口径，按[重新选路规则](03-routing.md#受阻后重新选路)先 grill 用户。无关新发现单列建议。

## 验收 hook

冷启动时先完成[项目 hook 注册与实测](07-executors.md)。后续通过同一账本入口送验，按本次候选再次核对实际证据。

1. 按原工作区派发审查，`task submit --candidate <版本>` 固定本次候选和每个来源文件的哈希。审阅者按约定方法核对这些版本。独立读原件时让审阅者能打开原件，记录具体段落、画面或行为。复跑时还须保留命令、实测结果和可回读的运行凭据。
2. 每批交回一份 UTF-8 JSON，包含任务、尝试、候选和每项实读版本、方法、结论。可改变分批顺序和 Worker。缺少原件、工具或时间时，保留已查批次，缺项继续待核验。下面是一批证据的格式示例。

   ```json
   {"task":"audit","attempt":1,"candidate":"v1","items":[
     {"id":"argument","source":"out/report.md","sha256":"<实读版本 SHA-256>","method":"read-original","outcome":"pass","finding":"第 4 段的三个数字逐一对应附表第 2 至 4 行"}
   ]}
   ```

3. 主控通过 `oma --root <项目> task verify --id audit --outcome pass --review-evidence batch1.json --review-evidence batch2.json` 提交所有批次。CLI 和 Python 的 `Verify` 在写入通过事件前共用此 hook。它要求每项恰好出现一次，来源、方法与冻结范围一致，实读哈希与送验版本及当前文件吻合，每项明确通过并给出具体发现。失败可在同一候选上补缺再提交。候选变更则走返工和重新送验。

审阅者负责判断证据是否支持业务结论。主控复核具体发现，任何反例或保留意见都应保留到解决为止。只有 skill 文本、没有本分支账本程序的宿主，可完成范围确认和分批审阅，最终状态保留待核验，直到同一账本执行放行检查。
